人口归属、所在地与流动设计
============================

状态
----
这是长期设计约束记录，不是已批准的数据结构或实现规格。普通人口继续采用聚合 Pop 群体模拟；不为普通居民建立持续运行的个人记录。

一、人口在世界中的组织关系
--------------------------
概念上需要区分三个层次：
- 势力（Faction）：政治管辖、组织关系与人口统计视图。势力人口应从其管辖/关联殖民地等权威数据派生，不能复制成另一份人口总账。
- 殖民地（Colony）：Pop 当前居住/驻留的地点。当前实现的 colony.populationGroups 是群体权威数据的存放位置，殖民地总人口由群体人数求和。
- 建筑（Building）：生产与工作地点。未来建筑 workforce 应记录实际雇佣/分配的群体引用及人数；受雇人口仍属于其居住殖民地，不能从殖民地人口或需求中扣除，也不能在建筑中重复计作第二份人口。

势力、殖民地、建筑不是三份平行人口容器。未来建筑就业关系应引用/分配现有群体人数，并明确一个群体的可用人数如何在多个建筑之间分配。

二、必须分开的关系
------------------
| 关系 | 语义 | 是否改变人口总数 |
| 当前所在地 | Pop 当前居住/驻留的殖民地 | 单纯变更位置不改变全世界总人口 |
| 政治管辖/归属 | 当前受哪个势力或政治实体控制 | 否 |
| 来源/籍贯 | 出生地、迁入来源或机器人制造/登记来源 | 否 |
| 雇佣/工作分配 | 哪些群体成员在何处工作 | 否 |
| 所有权/控制权 | 机器人等人口实体由谁拥有/控制 | 否 |
| 出生/制造 | 新人口产生 | 是，增加 |
| 死亡/报废/永久流失 | 人口退出模拟人口 | 是，减少 |
| 移民/调拨 | 人口从一个地点转移到另一个地点 | 否，全局守恒 |
| 离职/失业 | 解除就业关系 | 否 |

以上关系可能彼此独立。例如某企业制造的机械劳工可以归企业所有，被租赁到另一势力控制的殖民地，在当地建筑工作；制造来源、所有权、政治管辖、当前所在地和雇主不是同一个字段。

三、人口来源与所有权
--------------------
- 生物 Pop 可按群体保存出生地/原籍/来源地分布，但不需要为每个人保存籍贯。来源统计是可选维度，且不能与其他独立维度自动推导联合分布。
- 仿生人和机械劳工可能需要记录制造来源、登记来源和所有权。是否存在无主、公共持有、企业持有、租赁、委托运营等具体制度，留给未来游戏规则设计。
- 所有权不是人口所在地或政治归属。所有权转移不自动改变群体人数、居住地或雇佣关系。
- 不应现在就建立通用产权/租赁框架；只有出现真实机器人制造、企业资产或劳工调拨消费者时，再定义最小业务契约。

四、迁移与流失的守恒语义
------------------------
- 移民/调拨是跨殖民地群体数量的转移：来源减少、目的地增加，全世界总量守恒；两端更新必须原子完成。
- 若只迁移群体的一部分，必须明确 split 后两边的维度分布如何确定；沿用现有“独立边际、禁止隐式交叉”的原则。
- 出生/自然增长、机器人制造属于人口新增；死亡、报废、永久离开模拟世界属于人口减少。它们不是迁移。
- 失业、建筑关闭或岗位变化只改变就业分配，不等于人口流失。
- 政权更迭/殖民地易主只改变政治管辖关系，不自动改变 Pop 身份、来源或所有权。
- 迁移未来可能复用星际物流的路线/旅行时间/容量/风险约束；当前航行、星门和混合运输仅为世界设定，物流机制尚未实现。

五、对当前 Engine 地基的约束
----------------------------
1. 当前权威人口仍保存在各殖民地的 populationGroups；没有世界级迁移系统、群体全球唯一性、所有权表或来源地账本。
2. 当前人口群体的 split/merge/维度更新只在单殖民地群体集合中运行，不等于跨殖民地迁移已经实现。
3. 当前建筑 recipe workforce 只是 metadata，没有真实雇佣数据。
4. 不允许把派系人口统计、建筑雇佣人数或来源统计做成重复权威人口总量。
5. 未来若实现跨殖民地迁移，需要为群体拆分、来源/目的地同步、稳定 ID、交易失败回滚、存档迁移和 Mod 扩展契约设计聚焦方案；不能简单在两个殖民地分别调用独立 delta 伪装迁移。

六、执行顺序建议
----------------
- 近期：先推进群体级需求配置和共享库存分配，继续使用当前殖民地人口权威存储。
- 随后：在真实就业消费者出现时，设计建筑 workforce 引用/人数分配。
- 更后：有移民、机器人调拨或产权玩法消费者时，再设计来源、跨殖民地迁移、所有权和运输联动。
- 不要为了未来完整性提前增加人口全球账本、人口个体档案、所有权服务或通用迁移框架。
