### 2026-11-21 — campaign clock crash fix

- Investigated the user's Windows crash after setting the base game day to 10 seconds, starting a new world and selecting 4x speed. The supplied JSONL log showed the failure originated in the Electron campaign-clock callback, not in the launcher bootstrap, Mod loader, save migration or renderer.
- Root cause: `CampaignTimeController` correctly calls its `onAdvance` callback with the elapsed game-day number, but `electron/main.cjs` omitted that argument when calling `advanceCampaignTime`. The callback passed the options object in the elapsed-time position. `advanceClockTime` then rejected the non-finite value with `Elapsed game time must be between 0 and 36500 days`. The fatal cleanup called `pause()`, which ticked the same broken callback again and produced the secondary unhandled-rejection record seen in the user's log.
- Fixed the Electron callback to pass `elapsedGameDays` as the third argument, leaving event-bus and day-settlement options as the fourth argument.
- Added an integration regression test that drives a four-times-speed `CampaignTimeController` into `advanceCampaignTime` and verifies that 250 ms at a 1-second base day advances exactly one game day.
- Exact files changed: `electron/main.cjs`, `tests/engine.test.cjs`, `ASTRA_WORKLOG.md`.
- Starting main head: `dffc5f372fd459608eb150cc365570e3ddd66d9a`. Fix branch: `astra/fix-campaign-time-advance-2026-11-21`.

### 2026-11-21 — deterministic save/load integrity receipts

- Re-read the full root `AGENTS.md` and full `ASTRA_WORKLOG.md` before beginning this task. Starting main baseline: `6487063ddd32d23600a8260b20e0e183c7f9a909`. Main CI [44899192945](https://github.com/Sakurefa/test-game/actions/runs/44899192945) completed successfully on that baseline after the PR #5 merge/work-log update: syntax, 154/154 tests, renderer build and generated-renderer commit passed.
- Created branch `astra/save-load-receipt-2026-11-21` from the exact main baseline. All work remains isolated from main pending CI and review.
- Added a version-1 save receipt to the existing save-slot `metadata.ini`: SHA-256 of the exact serialized `data/world.json` bytes, byte count, world schema version, campaign day/date and content fingerprint. The digest is over the bytes written by the existing serializer; it is not a canonicalized second model of world state.
- Added `readGameStateWithReceipt` while preserving the existing `readGameState` API for autosave/legacy callers. A present receipt is checked against the actual world file bytes and the embedded world identity fields before the world is returned for schema migration and normal world validation.
- Compatibility: old save slots with no receipt still load as `legacy-unverified`; the next save adds a receipt. Partial/malformed receipt metadata is marked damaged, and a digest/byte/context mismatch rejects loading. Receipt verification is a load-boundary operation only; it is not called from the 100 ms campaign clock or ordinary simulation.
- Save failure boundary: slot metadata is validated before replacing the world file. If the metadata/receipt atomic replacement fails after the world file has been written, storage restores the previous world file (or removes the new file for a first save) before propagating the error.
- Main-process manual/new-world/load handlers now retain and log the receipt. Autosave completion records include their receipt. The save-slot page displays a short SHA-256 prefix and serialized byte count with an explicit “checked on load” label; successful loading displays the same prefix as verified. Legacy loads are clearly identified as lacking a prior receipt. A receipt is a local integrity fingerprint for accidental/partial changes, not a signature or tamper-proof authenticity guarantee.
- No game-state Schema version change, world JSON field, formula, RNG stream, scheduler cadence, domain event, Mod API, authoritative simulation state, engine logger, IPC command shape for world data, Electron runtime bootstrap or launcher distribution design was changed.
- Exact source/test/docs files changed: `electron/storage.cjs`, `electron/main.cjs`, `electron/autosave.cjs`, `src/main.js`, `tests/storage.test.cjs`, `tests/autosave.test.cjs`, `docs/ENGINE_ARCHITECTURE.md`, `docs/PLAYTEST_GUIDE.md` and `ASTRA_WORKLOG.md`.
- Added tests for deterministic repeated saves producing the same fingerprint, successful write/read verification and metadata display, changed world JSON being rejected, legacy no-receipt saves remaining loadable and gaining a receipt on their next save, malformed/partial receipt metadata being rejected, and daily/weekly autosaves retaining verified receipts.
