实现内容
--------
1. 新增 `engine/settlement.cjs`，导出 `settleSystemEvent()`。
2. Settlement 接收一个 System Event、candidate world、Resolution registry、计算/随机上下文和 Engine Effect executor。
3. Resolution 只接收 detached snapshot，并返回经过 registry JSON-safe 验证的 `{ result, effects }` 计划；Settlement 按序调用 Effect executor，返回结果与每项已应用 Effect 的实际结果。
4. Settlement 不管理 Trigger Queue、不写 Domain Event history、不承担 Presentation/UI；它只处理单个 System Event 的执行阶段。
5. `engine/triggers.cjs` 现在负责 due 检测、System Event 创建、调用 Settlement、写 `trigger.resolved`、pending 出队与 receipt。
6. Effect executor 仍由 Simulation 层注入，并复用原有 `applyModEffect` 白名单及 `mod.effect-applied` 事实记录。

测试覆盖
--------
- 新增 `tests/settlement.test.cjs`：验证 detached snapshot 不会改动权威 candidate world；只有 Effect executor 可以应用变更。

- 验证缺少 Effect executor 和异步 Effect executor 均被拒绝。
- 原 Trigger 集成测试继续覆盖 Resolution 结果、Effect 计划、Domain Event、receipt 和 candidate-world 原子回滚。
