## Engine / Mod 边界

- Engine 提供通用机制：数据装载与结构校验、Formula 执行/审计、System cadence/依赖调度、命名随机流、Mod Hook 执行、批准 Effect、Command、Domain Event、Trigger、Resolution、Settlement、持久化与原子结算。
- mods/core 是必需基础游戏内容 Mod，不属于 Engine。它可以通过 API v4 JS 提供基线玩法行为，但不包含 Engine 底层调度器、公式执行器、随机流、Trigger Queue 或 Event Bus。
- Mod manifest、registry、content definitions 和 localization 仍使用 INI。API v3 INI-only Mod 保持兼容；API v4 可显式声明 scripts/hooks、versioned formulas 与 recurring simulation systems。
- 具体游戏规则、数值、初始账户和玩家文本由 Mod 定义；Renderer 只展示状态，不成为游戏规则权威来源。

## 当前公式与模拟系统

- engine/formulas.cjs 不再内置人口需求/生产/商品价格/证券价格等游戏公式；CalculationService 默认公式集为空，负责注册/执行/审计 Mod 提供的版本化公式。
- engine/system-registry.cjs 仍提供 annual/monthly/weekly/daily/manual 通用调度、顺序与依赖拓扑；具体周期系统由 Mod manifest [systems] 声明。
- Core API v4 在 mods/core/scripts/simulation.js 提供基线生产、总人口需求、商品/证券定价与战争时间线行为；Core manifest 声明 4 个 recurring systems 与 4 个 Formula。
- 对应的商品/配方、生产效率、价格走廊、稀缺系数、调整速度、证券变动限制、货币/账户/开局余额都留在 Core INI。
- 新世界财务入口要求 Mod 提供货币与账户定义。旧 CR/player-main/system-treasury 开局结构仅保留在 createLegacyFinancialLedger 中，用于旧存档迁移。

## 当前地基与未实现内容

- World schema 9；旧 schema 1–8 迁移至 9。聚合 populationGroups 为殖民地权威人口数量；scalar population 是派生兼容投影。支持人口群体 split/merge/dimension update；独立维度是边际分布，不推导联合人口。
- Campaign clock、命名随机流、候选 World 日结算原子提交、版本化计算审计、命令运行时、财务账本、Domain Events、post-commit read-only Event Bus、Trigger/Resolution/Settlement 基础均已实现。
- Trigger 当前支持 date、elapsed-day、new Domain Event due sources；effect.apply、formula.effect、event.emit 三种 Resolution；13 种即时批准 Effect。条件/阈值来源、Command Resolution、通用 Modifier 生命周期、Presentation 仍未实现；没有真实消费者时不继续扩张。
- Core 当前人口需求仍为殖民地总人口 × commodity.daily_need_per_thousand，并执行共享库存受限消费；这只是过渡性的聚合人口需求规则，不是群体 Tag Need。
- Engine 已有单一维度类别份额选择原语 `matchPopulationDimensionCategories`，并新增 Mod 内容类型 `population_tag`：一个人口 Tag 映射到一个 dimension 及该维度内一个或多个 category（OR）。这是人口专用映射适配，不是全局 Tag Catalog；尚未形成 Need rule 或群体级需求结算。跨维度联合份额、Tag 组合、规则重叠去重和群体级报告仍未实现。共享库存执行接口已实现，策略由 Mod 提供；Engine 不设 pro-rata、公平配给、阶级优先或隐藏 fallback。
- 商品品质/市场相对档次/品质批次、购买力/工资、建筑 workforce、完整订单市场、跨殖民地物流、能源发电/容量/储能/调度、人口迁移/群体调拨仍未实现。
- engine/queries.cjs 的部分查询仍是只读 Core 世界模型投影；Effect whitelist 仍是有限、明确的领域状态转换 API，而非任意 World patch。

## 已确认的世界经济与人口前提

- Pop Group 的种族/物种类别由 Mod 定义；各类种族可以通过 Mod Tag / Need 规则拥有不同需求。Engine 不预设有机、仿生、合成或机械分类，也不从种族名称推断需求。
- 能源是受地点、技术和容量限制的战略瓶颈；未来需区分发电能力、实际供给、消耗分配、储能和可运输能源载体。
- 星际航行、星门和混合运输并存；不宜居殖民地也可培养食物，但自给自足成本可能极高。
- 当前所在地、政治归属、来源/籍贯、就业关系、所有权必须区分；群体人口数量只保留一份权威账本。建筑 workforce 引用居住人口群体，不应双重计数。

## 下一步方向与边界

继续先设计 Tag 驱动的群体 Need 最小契约，以及 Mod 决定共享库存短缺配额的策略接口：
1. 区分对象 Tag、人口维度份额与规则条件；Tag 匹配不得通过独立边际相乘推导联合人口。
2. 闭合多 Need 规则重叠、组合条件、人口份额去重和请求结果上下文。
3. 设计 Mod 策略的请求输入、分配结果、未覆盖/重复/未知请求、负数/超请求/超库存、精度与确定性契约。
4. Engine 只负责合法性、库存守恒、扣减与记录；不选公平原则，也不提供隐藏分配默认。
5. 设计完成后再实现最小机制与聚焦测试。

明确延后：财富/购买力、支付、阶级配额、工资、商品替代、商品品质批次、市场清算、能源基础设施、跨殖民地物流、人口迁移与产权/租赁框架。没有真实消费者前不提前建立对应通用抽象。
