### 2026-11-21 — Phase C foundation: validated commands and domain-event delivery

- Scope: close the gap between the existing simulation registry and persisted domain-event records by introducing a shared engine command boundary and a read-only event delivery contract. This batch deliberately adds no pretend gameplay: player trades, cargo transfers, construction, fleet orders and other concrete commands remain unregistered until their underlying world models are designed.
- Added `engine/commands.cjs`: stable command IDs/types, JSON-safe bounded payloads (8 KiB) and results (16 KiB), synchronous validation/authorization, immutable detached world views for guards, and isolated mutable world drafts for handlers. Optional post-transition validation runs on a frozen detached view. Handler or validation failure leaves the caller's world unchanged. Handlers are prevented from altering command receipts.
- Command idempotency: successful commands record a canonical type/payload signature, command ID, campaign day and result. Replaying the same ID and intent returns the prior result and does not execute or emit again; reusing an ID for different intent is rejected. The save retains the latest 256 receipts; this is a bounded retry window, not a replacement for permanent unique transaction IDs in a future financial ledger. Receipt signatures/results and duplicate IDs are validated at world-state boundaries.
- Added `engine/command-runtime.cjs`: wraps the dispatcher, commits returned event descriptors into the same world's persistent typed event history, then publishes only newly committed events. Event persistence conflict aborts the isolated draft before it can replace the original world. Delivery results are returned for caller-side diagnostics.
- Added `engine/event-bus.cjs`: exact-type and wildcard subscriptions, deterministic registration-order delivery, idempotent unsubscribe callbacks, immutable detached event snapshots, synchronous subscribers, isolated subscriber exceptions and explicit disposal lifecycle. The event bus does not grant subscribers a world-state mutation reference.
- Extended `engine/domain-events.cjs`: optional persistent idempotency keys; repeated same-key/same-fact emission within retained history returns the existing record, while conflicting reuse and duplicate saved keys are rejected. Existing market, active-war and weekly-colony events now use stable campaign-day/entity keys. The 300-record bounded history means this is a same-window settlement deduplication guard; future durable economic transactions need their own ledger-level uniqueness constraints.
- Integrated optional event-bus publication into `advanceDay`, `advanceDays` and `advanceCampaignTime`; simulation rules still run without a bus and do not depend on subscribers or renderer timing.
- Bumped world save schema 4 -> 5 for bounded command receipts. Schemas 1–4 migrate to schema 5 while preserving campaign time, existing state and typed event history where present. Updated storage read/write version gates.
- Updated `docs/ENGINE_ARCHITECTURE.md` and `docs/PLAYTEST_GUIDE.md` to describe the new contracts and explicitly state that the dispatcher is not yet wired to player-facing Electron IPC controls and that no trade/transfer/build/logistics/fleet commands are playable.

### 2026-11-21 — Phase D: main-process command gateway and extensible finance ledger

- Re-read the complete root `AGENTS.md` and complete `ASTRA_WORKLOG.md` before this session. Starting main head: `d21a48013e2ffeb24b7e642f0b1f7b36d0e00723`. The latest prior log-only commit did not have a readable successful Actions status, so prior command/event services were treated as unverified until this batch's full CI run.
- Connected the engine command pipeline to Electron through new `electron/world-command-gateway.cjs`. The gateway owns its domain-event bus and exposes only registered command types. Renderer IPC now submits a bounded command envelope through `world.dispatchCommand()`; the main process derives actor identity from the active world's player faction and does not accept actor, permissions or arbitrary handler names from the renderer. The only registered gateway command is currently `finance.transfer`.
- The gateway commits the isolated world draft and command receipt before publishing its events. The same event bus now receives both command-generated domain events and simulation settlement events from the campaign clock/manual day-advance path. Event subscribers therefore observe the committed active world, not the previous snapshot. Subscriber exceptions remain isolated by the event-bus contract.
- Hardened Electron lifecycle sequencing: saving blocks commands, speed changes and manual day advancement; world transitions block saves and commands; loading validates a detached world before swapping it into the active runtime; new worlds and initial save data are prepared before replacing the current world; failed initial save creation cleans up the incomplete slot. Save/transition locks are released through `finally` paths. The separately distributed launcher EXE was not changed.
- Added `engine/ledger.cjs` with a reusable double-entry style accounting core. The player account and system treasury are represented as accounts with stable owner IDs, currency, integer minor-unit balances, overdraft policy, status and positions. Ledger transactions contain 2–32 signed integer entries, must balance to zero for every currency, may reference each account only once, and have monotonic transaction IDs/sequences. Account balances are validated by replaying the append-only ledger; tampered projections, duplicate transaction command IDs, overdraws, unknown accounts, zero entries and unbalanced transactions are rejected. Appends/register operations validate a detached candidate before mutating the original ledger.
- Added registration services for additional account owners and currency definitions. New accounts begin at zero; they cannot create money by supplying a starting balance and must receive funds through a balanced transaction. The initial currency is CR with two minor digits. The initial player capital of 250,000 CR is represented as 25,000,000 minor units and balanced against the system treasury.
- Added `finance.transfer` as the first registered financial command. It checks source-account ownership against the trusted actor, account status, same-currency rules, positive safe-integer minor units and available funds; it writes the balanced ledger transaction and emits `finance.transfer-settled`. Cross-currency transfers are refused until an explicit exchange/clearing mechanism exists. No player transfer UI, market buy/sell order, share ownership transfer, loan, dividend, operating-cost or logistics-payment command is implemented yet.
- Bumped world-save schema 5 -> 6. New worlds store `player.accountId` and `finance` instead of a free-standing `player.account.cash` field. Schemas 1–5 migrate while preserving previous cash and holdings; the migration converts cash to CR minor units and records opening capital at the saved campaign day/date. Storage reads schemas 1–6 and writes schema 6 only. The player funds display now reads from the canonical player ledger account.
- Expanded tests for ledger balancing/rollback/validation, account and currency registration, overdraft limits, transfer authorization/idempotency, command replay reauthorization, commit-before-event ordering, event bus sharing, schema 1–5 migration and schema-6 storage. Updated the engine architecture, playtest guide and README. Fixed malformed documentation line breaks from the prior incremental updates.
