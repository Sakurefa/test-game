二、逐 Rule × Group 的需求行
----------------------------
新增 API v4 Hook 方法：evaluatePopulationNeedRule(colonyId, groupId, ruleId)。

对指定群体和指定规则计算一条独立需求行，包含 ruleId、populationTagId、groupId、commodityId、dimensionId、categoryIds、dimensionPresent、matchedProportion、matchedPopulation、dailyNeedPerThousand 与 requested。

requested = matchedPopulation / 1000 × daily_need_per_thousand；不进行显示舍入。
- 目标维度不存在时，matchedProportion、matchedPopulation 与 requested 均保持 null/unknown；不会把未知转成 0。
- 维度存在但匹配类别份额为零时，requested 是数值 0。
- 每次只评估一个 Rule × 一个 Group；不同规则即使命中相同人口份额也分别返回。
- Engine 不自动累加、去重、覆盖或按文件顺序设优先级；重叠语义由 Mod 决定。

三、请求来源追溯
----------------
扩展 colony.stockpile.allocate 请求，新增可选 sourceId。
- id 仍是 Mod 为本次完整计划内每条请求提供的唯一请求 ID。
- requesterId 继续标识请求方，例如 Pop Group ID。
- sourceId 是可选的稳定来源内容 ID，例如 Need Rule ID；Engine 验证其稳定 ID 格式并在逐请求 allocation result / audit 中原样保留。
- 未提供 sourceId 的既有请求保持原返回结构。
- 同一商品可有多个独立请求。Engine 保留每条请求结果，只在同商品库存扣减与库存守恒检查时聚合分配量。
- 若 Mod 把多个 Rule 源聚合为一条请求，单一 sourceId 无法表达多来源；Mod 自己保存来源列表/归并明细。
