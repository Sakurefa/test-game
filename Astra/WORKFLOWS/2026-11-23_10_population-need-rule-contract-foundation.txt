二、最小 Need Rule 内容契约
--------------------------
新增内容类型：population_need_rule

INI 示例：

    [population_need_rule.need.humanoid-food]
    population_tag_id = tag.humanoid
    commodity_id = food
    daily_need_per_thousand = 0.25

Registry：

    [entry.need.humanoid-food]
    type = population_need_rule

语义：
- 每条规则一个 Population Tag、一个 Commodity 和一个正数 daily_need_per_thousand。
- 率的含义是每游戏日、每 1,000 名命中人口所需的商品数量；商品 ID 和数值全部由 Mod 定义。
- 这是一条需求规则描述，不是 NeedProfile 人口实体或独立人口分类。
- 每条规则只引用一个 Tag；Tag 又只指向一个人口 dimension。因此当前规则不表达跨独立维度 AND，也不推导联合人口。
- Catalog 校验 Tag / Commodity 引用与正数需求率；规则在存在时进入序列化 Catalog 与内容指纹。空 populationNeedRules 不序列化，避免无规则 Mod 被无意义改变旧内容指纹。
- Mod Hook 可从 input.catalog.populationNeedRules 读取规则。Engine 不自动合并、去重、覆盖或按文件顺序解释多条规则；同一人口命中多个规则时的累加/冲突、同商品请求汇总与 rule/group 结果关联，均由 Mod Hook 定义。
- 规则未知人口份额时，匹配 API 返回 unknown/null。是否停止结算或采用其他 Mod 语义，不由 Engine 偷偷将其视为零。
- Engine 不实现公平、按比例或阶级优先分配；策略仍由 Mod 提交给已有 colony.stockpile.allocate。

三、API v4 Hook 匹配入口
-----------------------
新增只读 API：

    api.matchPopulationTag(colonyId, groupId, tagId)

- 从当前 Hook detached world 快照按 colonyId / groupId 找到人口群体，从序列化 Catalog 查找人口 Tag。
- 使用既有 matchPopulationDimensionCategories 完成精确的单维度 OR 匹配。
- 返回 groupId、dimensionId、categoryIds、dimensionPresent、matchedProportion、matchedPopulation。
- 目标群体不存在或 Tag 未注册时明确报错；目标维度不存在时返回 dimensionPresent:false 与 null matched values。
- 只返回新建匹配结果对象，不暴露可修改 World 引用；不读写正式 World。
- 仅新增 Hook helper；没有把 Formula executor、Node 或 Electron 宿主能力暴露给 Mod。
