关于接下来的工作
==================

当前阶段是通用 Engine 开发，不是直接实现人口经济玩法。所有可运行的游戏内容都由 `mods/` 下的 Mod 提供；`mods/core` 是必需的基础内容 Mod，本身不属于 Engine。Engine 负责可复用的数据表示、装载、验证、结算、持久化与扩展接口；具体分类、规则、效果配置和数值由 Core/可选 Mod 通过 INI 提供。

已完成的 Engine 地基：
1. World schema 8 的通用聚合人口群体存储。**人口群体的人数是权威人口记录；殖民地总人口等于所有群体人数之和。**标量 `population` 仅作为兼容/读取投影，由 Engine 从群体重新汇总，不是另一份人口账本。每组包含稳定 ID、人口数量和独立统计维度；每个维度内部比例合计为 1，不同维度不生成隐含联合分布。
2. Mod INI 初始群体声明契约。Mod 注册 `population_group`，使用 `colony_id`、`population` 和 `dimension.<id>` 定义群体。只要任一启用 Mod 为殖民地声明群体，这些群体就构成完整初始人口，其人数之和直接定义运行时总人口；不要求与 colony 定义中的 fallback `population` 相等，不额外补 `unclassified`。只有完全没有群体定义时，才从 colony `population` fallback 创建一个中性群体。
3. 人口群体运行时变更契约。旧 `colony.population.delta` 继续表达真实总人口增减：正增量进入 `unclassified`，负增量按现有人群比例扣减，操作后重新汇总总数。新增 Mod Effect 支持群体拆分、合并和维度分布更新。拆分从一个已有群体转移人数到新群体；合并按人数加权各独立维度并移除来源群体；维度更新只改变统计分布。拆分/合并不改变殖民地总人口；拆分时可选重指定两组分布，但必须守恒每个独立维度内各类别的人数。所有效果沿用现有 `mod.effect-applied` Domain Event 记录 Mod 来源、原始输入与实际结果。
4. 查询投影 `colony.summary` 提供群体快照，并从群体汇总总人口；派系摘要同样取派系殖民地的人群总数。现有需求系统仍只消费派生总人数，无需理解人群维度。

兼容与约束：
- Schema 1–7 旧存档只有标量总人口；迁移时一次性将旧值转换成中性 `unclassified` 群体。迁移以后群体人数成为权威数据，标量只作一致性投影检查。
- schema 8 持久化字段形状未改变，仍保持现有内容指纹兼容策略。
- Core 目前没有实际人口群体和人口构成比例；因此当前 Core 世界仍从 fallback 生成单一 `unclassified` 群体。没有新增具体阶级、职业比例、工资、需求篮子或经济平衡规则。
- 每日需求仍按殖民地派生总人口聚合结算，并非群体级需求。不要把存储、初始化、查询与重组接口描述成完整人口经济系统。

下一项待设计的通用 Engine 地基：检查现有 Query、Mod hook 输入、事件与调度触发接口，确定如何让 Mod 以声明式条件引用派生的殖民地总人口（例如规模门槛、达到/跨越阈值时触发）。Engine 提供通用数值读取、条件判断和触发时机；具体阈值、效果与内容语义仍由 Mod 定义。先审现有接口与持久化需求，不要先实现某款游戏的殖民地等级或人口奖励规则。

每一步保持小而可测试，并同时遵守 AK 原则与 MOD 化原则。
