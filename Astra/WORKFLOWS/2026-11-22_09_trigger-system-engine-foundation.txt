已固定的语义边界
----------------
- Trigger 是持久化的单次调度实例；不承担 recurring cadence。
- System Event 是 Trigger 到期时创建的短生命周期内部处理请求；不是玩家可见叙事事件。
- Resolution 是 Engine 注册的处理入口；Effect 是实际世界状态变化。
- Domain Event 是已发生事实；它记录在 world history，且只在 world commit 后经只读 Event Bus 发布。
- Presentation 将来负责把已提交事实转成 UI；本阶段不涉及。
- 日历日期复用 `engine/clock.cjs`；经过时间按完整 campaign-day 处理，不支持 dayFraction 子日触发。

阶段一执行契约
--------------
- 每日顺序：campaign clock 推进 → 处理此前到期 Trigger → campaign.before-day → annual/monthly/weekly/daily cadence systems → campaign.after-day。
- 当前 settlement 新建的 Trigger 最早在下一个完整日边界执行，避免同一边界的递归触发。
- due kinds 支持 date 和 elapsed；Trigger ID 必须使用 owner Mod 命名空间。相同 ID/相同定义去重；冲突定义报错。
- 第一阶段只有 `effect.apply` Resolution，复用现有受检 `applyModEffect`；调度时在副本上预验证，执行时再次校验。
- 已成功处理的 Trigger 写入 `mod.effect-applied` 与 `trigger.resolved` Domain Event、移出 pending 并登记最近 receipt；回执最近 256 条。
- Trigger、Effect、Domain Event、出队与 receipt 均属于 detached candidate world 事务；失败整日回滚。
