关于现状
========

当前阶段：通用 Engine 地基建设。目标是提供稳定、可复用、简单可靠的模拟机制；所有可运行的游戏内容与规则继续由 `mods/` 下的 Mod 提供。 `mods/core` 是必需的基础内容 Mod，不属于 Engine。Mod 内容和玩家可见文本仍通过 INI 定义；API v4 JS 仅使用明确声明的 hooks 和受限结果契约，API v3 INI-only Mod 继续兼容。

## 已有底层

- World save schema 9；旧 schema 1–8 均有迁移路径。Schema 8 保存会保留已有群体/经济等数据，并新增空 Trigger Queue。
- Simulation system registry 支持 annual、monthly、weekly、daily、manual cadence。年度在 1 月 1 日到期，月度在每月 1 日到期，周度按每七个经过日，日度按每个完整游戏日；周期系统同日顺序为 annual → monthly → weekly → daily。
- 当前真实周期系统仍是周度殖民地生产，以及日度人口需求、市场报价和战争时间线；尚无实际 annual/monthly 游戏系统消费者。
- 每日结算在 detached candidate world 上运行；所有触发动作、系统、Hook 和 Domain Event 写入都在候选世界内，成功后提交，失败则丢弃候选。Event Bus 只在提交后发布新 Domain Event。
- 已有命名随机流、版本化计算服务、typed Domain Event 历史、只读 Event Bus、命令分发器、主进程命令网关、财务账本、Mod API v4 与只读查询投影。

## Trigger System 第一阶段

- 新增独立的持久化 Trigger Queue，保存待执行实例及最近处理回执；不替代 recurring simulation-system cadence。
- 当前 due source 仅支持有效日历日期与经过整数个完整 campaign day；日期规则复用 `engine/clock.cjs`，不支持子日触发。
- Mod API v4 hook 可以返回 `triggers`。Trigger ID 由所属 Mod 命名空间约束；同 ID、同定义重复创建会去重，同 ID、不同定义会报错。
- 每个完整日结算开始时，Engine 先推进时钟，再处理已有到期 Trigger，随后执行 `campaign.before-day`、年度/月度/周度/日度系统，最后执行 `campaign.after-day`。本次结算期间新建的 Trigger 最早在下一个完整日边界运行，避免同一边界递归触发。
- Trigger 到期时创建短生命周期 System Event。当前注册 `effect.apply` 与 `formula.effect` 两种 Resolution；它们都返回 `{ result, effects }` 计划。独立 `engine/settlement.cjs` 接收 System Event 并执行 Resolution/Effect 计划；Trigger Runner 只负责调度、事实记录、出队与回执。`formula.effect` 只调用已有版本化 Engine 公式，以 Trigger ID 生成独立随机流，并用顶层 `resultFields` 映射公式结果。Trigger 不能存储任意 JS 函数、Mod callback 或 world patch。
- System Event 是待 Engine 处理的请求；Domain Event 是已经发生的事实。Settlement runner 不负责调度或写历史；成功处理会在候选世界记录每个 `mod.effect-applied` 和 `trigger.resolved`，Event Bus 在世界提交后才收到它们。Presentation/玩家可见文本不属于 Trigger Queue。
- Queue、Settlement 结果、Effect 变更、Domain Event 和处理回执处于同一个 candidate-world 事务。处理失败时整日回滚，待处理 Trigger 仍保留。
- 近期回执保留 256 条；在回执窗口内可防止已处理 ID 被重复执行。该机制不是永久全局 ID 数据库。

- Resolution 结果对象与 Effect 计划是分离字段；每次最多 16 个 Effect。
- `formula.effect` 的输入在 Trigger 调度时捕获；它只能选择 Engine 已注册公式，并通过顶层结果字段映射向已注册 Effect 填值，不提供公式表达式/回调扩展。
- 公式使用按 Trigger ID 派生的稳定随机流；结果记录与流状态在 candidate world 成功后一起提交。

## 人口与经济现状

- 人口采用聚合群体模型；群体人数是权威记录，殖民地总人口等于所有群体人数之和，标量 `population` 仅作为派生兼容投影。
- Mod 可通过 INI 的 `population_group` 定义完整初始群体。没有群体定义时才从 colony fallback population 创建单一 `unclassified` 群体。
- 群体支持 split、merge 和维度分布更新；这些群体重组不改变人口总量。
- 当前每日需求仍按殖民地总人口聚合计算，没有按群体分别结算；Core 尚未写入实际人口构成。
- 每周生产已存在，但配方 workforce 仍只是 metadata；实际雇佣群体、工资、人员池和建筑 workforce 结算尚未实现。

## 尚未实现

- 条件/阈值触发与 Domain-Event-driven Trigger source。
- 除 `effect.apply` 与 `formula.effect` 外的 Command/Event 等 Resolution 类型。
- 临时效果状态、生命周期与对应到期动作；通用 source/target/operation/value 数值修改器。
- 建筑实际雇佣 workforce 数据、结算快照与条件效果稳定期。
- 人口分组需求消费、商品市场清算、工资与完整生产经济规则。
