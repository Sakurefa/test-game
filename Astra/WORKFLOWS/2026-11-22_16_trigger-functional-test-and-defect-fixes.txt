## 目标

按既有 Trigger System 设计审查实现缺口，修复已确认缺陷，并通过真实 Mod loader 和每日结算路径验证当前全部已实现 Trigger/Resolution/Effect 能力。保持 AK 原则与 MOD 化原则，不把测试内容塞入 Engine 或必需 Core。

## 修正

1. `engine/triggers.cjs`
   - Trigger definition 自身的 System Event payload 仍受 16 KiB 上限。
   - Domain Event source snapshot 不再错误复用该较小上限，完整保留合法 JSON-safe 来源事实。
2. `engine/simulation.cjs`
   - 移除 `validateDayInputs()` 中重复的 Trigger Queue 完整校验。
   - `processDueTriggers()` 仍在独立执行入口统一校验；`validateWorldState()` 仍在世界/存档边界验证队列。
3. 测试覆盖
   - Domain Event 历史接受 32 KiB JSON-safe payload。
   - 匹配后的 Trigger source snapshot 可完整保存 32 KiB payload，不受 Trigger definition payload 上限影响。

## 中间测试问题与处理

- 首次尝试给 Domain Event payload 增加 12 KiB 上限，CI 显示这会与 Trigger source snapshot、`trigger.resolved` 的完整来源上下文产生新边界问题。最终撤回该新增限制，改为仅让 source snapshot 不继承 Trigger definition 的 16 KiB payload 上限。
- 测试 Mod 曾短暂置于正式 `mods/` 目录，导致不显式排除该 Mod 的既有测试意外加载它。已将 fixture 移入 `tests/fixtures/`，并在测试中复制真实 Core/example-market 包到临时目录后单独加载。
- fixture 的 JS 文件路径随后修正为 manifest 声明的 `scripts/trigger-test.js`。
