二、实现内容
------------
1. Engine 新增通用 Mod Effect：`colony.stockpile.allocate`。
2. 输入：
   - colonyId；
   - requests：每条包含 id、requesterId、commodityId、requested；
   - allocations：每条包含 requestId、allocated。
3. Engine 验证：
   - 殖民地存在、库存结构合法；
   - 请求数组与结果数组长度一致且受 2048 条上限约束；
   - 请求与请求方 ID 符合稳定 ID 格式，且请求 ID 唯一；
   - commodity 必须存在；
   - requested / allocated 必须为有限、非负数；
   - allocation 只能引用已提交请求，不能重复或缺失；
   - 每条 allocated 不超过对应 requested；
   - 同商品所有 allocation 的合计不超过殖民地现有库存。
4. 所有商品库存变更先完成验证，再执行写入；非法计划不会造成部分库存扣减。
5. 返回逐请求 requested / allocated / unmet / satisfaction，以及逐商品库存 before / allocated / after。沿用现有 `mod.effect-applied` Domain Event，不引入第二套审计或状态记录。
6. 同一 Hook 调用中，同一殖民地只允许一份完整分配计划，防止多个 Mod 基于同一份库存快照提交互相竞争的方案，再由执行顺序或加载顺序隐含决定结果。
7. Engine 不实现 pro-rata、平等配给、阶级优先或其他公平/分配理念；合法 Mod 方案按其值执行。Pro-rata 仅能由具体 Mod 主动选择。
8. Core 的每日总人口聚合 Need 已接入该 Effect。当前 requester 暂时为 colony，Core 仍决定原有 aggregate 请求和库存受限分配数量。这是旧规则接入执行边界，不等于完成 Pop Group 级 Need。
