基线与目标
----------
- 基线 main：`b211f5c8340504e8552d8937e69d042dafdd8e22`。
- 目标：为已注册 Engine Resolution 增加可选 Domain Event 输出，使 Trigger 在完成一次批准结算后产生新事实，并可激活另一个等待该事实的 Trigger；不接入玩家命令网关，不开放 Event Bus 写权限或任意 Mod callback。

实现内容
--------
1. 新增共享 `normalizeDomainEventDescriptor()`，由 Domain Event 写入器与 Resolution plan 校验共同使用，保持 type/scope/subject/payload 规则一致。
2. Resolution plan 从 `{ result, effects }` 扩展为 `{ result, effects, domainEvents? }`。Effects 最多 16，Domain Event descriptors 最多 16；两类描述独立校验。
3. 新增 Engine Resolution `event.emit`。它接收本地事件 type 后缀和可选 object payload；Engine 从 Trigger sourceId 注入 Mod owner，将输出 type 限定为 `mod.<owner-mod-id>.<type>`，scope 固定为 `mod`、subjectId 固定为 owner Mod ID，payload 自动带入 `modId` 与 `eventType`。
4. Settlement 验证/执行 Resolution 计划并返回 Domain Event descriptors，但不写 history、不负责队列或 Event Bus。
5. Trigger Runner 在 candidate world 中应用 Settlement Effects 后，写入计划中的 Domain Events，再写 `trigger.resolved`（记录生成事实 ID/sequence/type）、移除 pending 并保存 receipt。该事实通过既有 emitter 激活匹配的 pending Trigger；dueDay 为事实日 + 1，不在当前 due 列表递归运行。
6. 没有新增 World schema 字段；旧 date/elapsed/Domain Event due Trigger 格式保持不变。
