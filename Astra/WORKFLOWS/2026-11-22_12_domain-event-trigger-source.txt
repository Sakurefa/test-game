- 目标：为持久化 Trigger 增加一次性 Domain Event due source；只响应订阅建立后的新事实，复用既有 Trigger Queue、System Event 与 Settlement，不扫描事件历史、不建立 EventBus gameplay listener，不新增 World schema。

实现内容
--------
1. 新增 due descriptor：`{ kind: "domain-event", type, scope?, subjectId? }`。type 必填；scope/subjectId 若提供则精确匹配。
2. Domain Event emitter 在 candidate world 新增事实时检查 pending Trigger。重复 idempotency key 返回旧事实、sequence 不前进时不会再次激活。
3. 命中后将 JSON-safe source event snapshot 存入 pending Trigger，并将 dueDay 设为 sourceEvent.day + 1；只在下一完整日边界结算。
4. Source snapshot 随 System Event、`trigger.resolved` 和 receipt 传递；bounded Domain Event history 即使裁剪旧事实，也不会抹去 Trigger 的来源上下文。
5. 只扫描 bounded Trigger Queue（上限 4096），不扫描 Domain Event history（保留上限 300）。Event Bus 继续只在 world commit 后发布已提交事实。
6. 既有 date/elapsed Trigger signature 保持原语义；Domain Event due 的 signature 不依赖激活后变化的 dueDay。未增加 schema 字段或升级版本，World schema 仍为 9。
