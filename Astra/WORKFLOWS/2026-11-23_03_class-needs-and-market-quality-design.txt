本轮新增/澄清的设计方向
----------------------
- 保留现有 Mod-defined species 人口维度，兼容人类、外星人及未来智慧生命。Engine 只处理通用 Pop Group，不为不同生命形态建立硬编码运行时实体类型。
- Species 不自动决定 Need Profile；职业、阶级/阶层、财富与法律身份分别表达不同语义。奴隶身份不是物种；不要把 wealth_tier 自动等同阶级。
- 阶级/生活水平标准影响 Need 商品的可接受/期望档次。数量消费满足与品质/生活水平满足需要分开表达。
- 商品可以拥有多个标签（例如碳水、蛋白质），不同标签可具有不同品质贡献；生产建筑/工艺可以修正最终品质，负面加工标签可以降低品质。具体品质聚合公式与标签权重未决定。
- 商品相对档次应在具体市场、具体需求品类中与竞争商品比较，不是商品永久固定的档次。市场基准如何加权、如何避免单一商品市场自动成为平均档次，仍未决定。
- Need Profile 必须明确对应人口数量。显式 need_profile 维度可作为候选，表示各需求群体的直接人数份额；不能用 class/species/profession/wealth 独立边际相乘推导交叉人口。
- 若同一 commodity ID 因建筑/工艺而产生不同品质，当前数量型 stockpile 会丢失品质来源；未来需明确商品变体/品质批次或其他表达。本阶段不实现。

当前结论与未决问题
------------------
1. 可以继续推进 Need Profile 设计，但需要确认它如何表达 class/social standard 与不同 Species 的需求差异；若两者共同决定需求，必须显式保存联合需求归属，而不能推导边际交叉。
2. Need Profile 的结构应至少能描述需求类别、数量需求与品质/档次标准；具体档案、标签、商品映射和数值属于 Mod INI。
3. 共享库存分配仍需确定公平性/优先级/比例规则、确定性排序，以及群体短缺报告。
4. 商品标签品质、市场相对档次、商品价格/购买力、最终满意度是不同层次；不要在第一版需求机制中混成一个公式。
5. 能源仍是边界案例：未来需求可以由 Need Profile 表达，但发电容量、功率调度、储能、能源网络和跨星系市场继续延后。
6. 商品品质批次库存、商品替代、购买力/支付、订单撮合、市场清算与物流不进入当前实现范围。
